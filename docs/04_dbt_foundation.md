# dbt Foundation:  Steam Data Platform

## Overview

Set up the dbt Core foundation for the Steam Games & Reviews Data Platform, using Snowflake as the data warehouse.

This phase focused on configuring the transformation environment before implementing any SQL models.

**Branch:** `feat/dbt-foundation`  
**Status:** Completed and merged into `main`

## Changes Made

### 1. dbt Project Configuration

Updated `dbt_project.yml` to organize models into three layers:

| Layer | Snowflake Schema | Materialization | Purpose |
|---|---|---|---|
| Staging | `STAGING` | View | Clean and standardize raw data |
| Intermediate | `INTERMEDIATE` | View | Joins, business logic, and the fact and dimension tables (see [doc 13](13_conceptual_model.md)) |
| Marts | `MARTS` | Table | Analytics-ready data |

Removed the default `models/example/` files generated by `dbt init`.

### 2. Schema Naming Macro

Created `macros/generate_schema_name.sql`.

- Overrides dbt's default schema naming behavior.
- Uses the custom schema specified in `dbt_project.yml`.
- Avoids unwanted schema names such as `STAGING_STAGING`.
- Configured to use the existing Snowflake transformation schemas.

### 3. dbt Dependencies

Created:

- `packages.yml` — declares `dbt_utils` v1.4.1.
- `package-lock.yml` — locks the resolved package version.

Dependencies were successfully installed using `dbt deps`.

### 4. Validation

| Command | Result |
|---|---|
| `dbt debug` | Snowflake connection passed |
| `dbt deps` | dbt_utils 1.4.1 installed |
| `dbt parse` | Parsed successfully |

Three unused configuration warnings are expected because no SQL models exist yet.

Schema naming was only parsed at this point. It was checked later through model execution, see [doc 10](10_dbt_sources_staging.md).

## Current Architecture

`Steam Data → dlt → STEAM_RAW → dbt Staging → dbt Intermediate (facts and dimensions) → dbt Marts → Streamlit`

Only the infrastructure and dbt configuration are ready. Data ingestion and transformation models have not yet been implemented.
